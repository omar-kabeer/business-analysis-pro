# Changelog

All notable changes to this project will be documented in this file.

## Unreleased

- Initialized Business Analysis OS repository structure.
- Rewrote all 14 specialist skills to the skill-authoring standard: pushy trigger-rich single-line descriptions, structured bodies (role, inputs, workflow, outputs, quality gates, stop conditions), BABOK and modern product-management alignment, and progressive-disclosure `references/` files.
- Added four skills to the OS: `natural-prose-editor`, `technical-writer`, `proposal-writer`, and `prompt-master` (adapted to the repository validator).
- Established a house editorial style in `docs/methodology/editorial-style.md` with a hard no em dash rule, wired into `CLAUDE.md` and `AGENTS.md` so `natural-prose-editor` runs as the final pass on every prose deliverable.
- Extended `scripts/validate-assets.mjs` to reject em dashes in deliverable and template markdown.
- Expanded `docs/architecture/skill-authoring-guidelines.md` with description-triggering, three-tier progressive disclosure, degrees of freedom, structured-prompt, and house-style guidance.
- Deepened `skills/business-analysis/references/babok-knowledge-areas.md` into a full BABOK v3 reference (BACCM, requirements classification, stakeholder roles, six knowledge areas with all tasks, the 50 techniques, competencies, perspectives, and a standards-based workflow).
- Packaged the OS as a Claude Code plugin under `plugin/` with a marketplace catalog at `.claude-plugin/marketplace.json`, a SessionStart house-style hook, and a `scripts/build-plugin.mjs` sync so `skills/` remains the single source of truth (`npm run build:plugin`).
- Added continuous integration (`.github/workflows/validate.yml`) that validates skills and templates, builds the plugin, and fails if `plugin/` drifts from source; added a root `.gitignore`.
- Started the templates library with the discovery and elicitation set (`stakeholder-register`, `stakeholder-map-raci`, `interview-guide`, `workshop-plan`), each aligned to BABOK v3 and domain-neutral. Generalised `validate-assets.mjs` to enforce frontmatter (type, domain, status, version) on every template.
- Added the strategy and analysis template set (`current-state-assessment`, `future-state-definition`, `gap-analysis`, `swot-analysis`, `business-model-canvas`), aligned to BABOK Strategy Analysis (6.1, 6.2) and techniques (SWOT 10.46, Business Model Canvas 10.8, Business Capability Analysis 10.6).
- Added the business case and finance template set (`business-case`, `executive-summary`), aligned to BABOK Business Cases (10.7) and Financial Analysis (10.20: NPV, IRR, payback, ROI, TCO, sensitivity) with pyramid and SCR executive structure.
- Added the requirements template set (`prd`, `frd`, `srs`, `nfr-specification`, `user-story-epic`), aligned to BABOK requirement quality (7.2), Non-Functional Requirements Analysis (10.30), Use Cases (10.47), User Stories (10.48), Acceptance and Evaluation Criteria (10.1), INVEST, and ISO/IEC/IEEE 29148.
- Added the product template set (`product-roadmap`, `product-vision-brief`, `prioritization-matrix`, `opportunity-solution-tree`, `go-to-market-plan`), grounded in modern product management (north-star, JTBD, opportunity solution trees, RICE and Kano prioritisation).
- Added the governance template set (`raid-log`, `risk-register`, `decision-log`, `requirements-traceability-matrix`, `release-readiness-checklist`), aligned to BABOK Item Tracking (10.26), Risk Analysis and Management (10.38), Trace Requirements (5.1), and Verify/Validate Requirements (7.2, 7.3). Completes templates library tranche 1.
- Fixed a duplicate-hook load error by removing the redundant `hooks` field from the plugin manifest (the standard `hooks/hooks.json` is auto-loaded); bumped the plugin to 1.1.0.
- Added `docs/methodology/sdlc-playbook.md`: how to use the OS across the SDLC (recommended hybrid iterative-incremental approach, phase-to-skill-to-template-to-gate map, and delivery-model tailoring). Shipped with the plugin.
- Added the checklists group (`definition-of-ready`, `definition-of-done`, `requirement-quality-review`, `business-case-review`), aligned to BABOK requirement quality (7.2), Business Cases (10.7), and INVEST. Extended `validate-assets.mjs` to enforce checklist frontmatter and scan checklists for em dashes; the build now ships checklists in the plugin. Bumped plugin to 1.3.0.
- Expanded `PLAN.md` into a full implementation plan (status snapshot, remaining work by roadmap phase, MVP proof next step, cross-cutting standards, sequencing, and housekeeping) and put it under version control.
- Re-evaluated the skills against BABOK v3 and the skill-creation research (`docs/methodology/skills-audit.md`). Added five specialist skills (`process-modelling`, `data-analysis`, `agile-coach`, `vendor-evaluation`, `communication`) so every BABOK v3 technique now has an owning skill; added `docs/methodology/technique-index.md`. Fixed authoring gaps: reference files for `architecture` and `ux`, and a stronger `prompt-master` description. Now 23 skills; plugin 1.4.0.
- Proved the MVP flow end to end (`examples/customer-self-service-portal/`): an unstructured request taken to a completed, traceable BRD and graded against a reusable rubric (`evaluation/brd-rubric.md`), scoring 25/27 (pass). Extended `validate-assets.mjs` to require the MVP assets and to scan examples and evaluation for em dashes. Shipped the rubric in the plugin; plugin 1.5.0. Closes the core of roadmap Phases 6 and 7.
- Phase 4 frameworks: consolidated reusable frameworks into `frameworks/` (prioritisation, discovery, strategy, decision, requirements-and-delivery), each with purpose, when to use, method, and pitfalls. Added `frameworks/` to the em dash scan and the plugin build. Plugin 1.6.0.
- Phase 5 domain packs: added `domain-packs/payments-iso20022/` (overview, terminology, regulation, and payments deliverables: payment-message-mapping, reconciliation-requirements, payments-compliance-checklist), grounded in current sources (ISO 20022 cross-border coexistence ended Nov 2025; PSD3 and PSR provisionally agreed Nov 2025; SEPA Instant and Verification of Payee live). Added a reusable `domain-packs/_template/`, an orchestrator routing entry, the domain-packs em dash scan, and plugin sync. Plugin 1.7.0.
- Added three Claude Code subagents in `agents/` (`requirements-verifier`, `deliverable-critic`, `market-researcher`) for isolated verification, critique, and research fan-out. Extended `validate-assets.mjs` to check agent frontmatter; the build ships agents in the plugin. Plugin 1.8.0. Note: subagents run in Claude Code only, not the chat interface.
- Updated `PLAN.md` to reflect completed Phases 4 and 5, the MVP proof, and the three subagents (plugin 1.8.0), and re-sequenced the remaining work (evaluation rubrics, template expansion, second example, further domain packs).
- Phase 3 expansion: added seven templates filling skill-to-template gaps (`process-model`, `use-case-specification`, `data-dictionary`, `journey-map`, `status-report`, `meeting-notes`, `rfp`), each BABOK-anchored. Updated `docs/methodology/technique-index.md` to reflect the new template coverage. 34 templates; plugin 1.9.0.
- Added evaluation rubrics for the business case and PRD (`evaluation/business-case-rubric.md`, `evaluation/prd-rubric.md`). Added two specialist skills completing explicit BABOK knowledge-area coverage: `solution-evaluation` (KA 6) and `ba-planning` (KA 1). Now 25 skills with all six knowledge areas owned; plugin 1.10.0.
- Phase 3 expansion tranche 2: added `persona`, `empathy-map`, `context-diagram`, `business-rules-catalogue`, and `okrs` templates; updated the technique index. 39 templates; plugin 1.11.0.
- Added a second full-life-cycle worked example (`examples/supplier-invoice-approval/`): an unstructured request taken through the three SDLC gates (invest via a graded business case, build via INVEST stories, release via a completed readiness checklist with a go decision) plus a post-launch solution-evaluation note. Complements the discovery-to-BRD example.
- Added a second domain pack `domain-packs/healthcare-hl7-fhir/` (overview, terminology, regulation, and deliverables: fhir-resource-mapping, healthcare-compliance-checklist), grounded in current sources (FHIR R4 production; US Core v7 with USCDI v5; CMS Interoperability rule effective Jan 2026; TEFCA to FHIR by 2026; HIPAA baseline). Demonstrates the reusable `_template/`. Added an orchestrator routing entry; plugin 1.12.0.
- Refreshed `PLAN.md` to the current state (plugin 1.12.0): 25 skills with all six BABOK knowledge areas owned, 39 templates, 3 evaluation rubrics, 2 domain packs, 2 worked examples, and 3 subagents.
- Housekeeping: seeded `memory/` (project context, glossary, stakeholder directory, decision register), `prompts/` (orchestrator intake, discovery kickoff, deliverable request, review request), and `deliverables/` (a full deliverable catalogue mapping deliverables to templates, skills, and rubrics). Rewrote the `docs/` stub READMEs (babok, frameworks, product-management, templates, examples, methodology) as real indexes pointing to the assets. Extended the em dash scan to `memory/` and `prompts/`.
- Updated `PLAN.md` housekeeping to reflect the seeded `memory/`, `prompts/`, and `deliverables/` and the doc indexes.
- Excluded internal planning docs (`PLAN.md`, `CODEX_IMPLEMENTATION_GUIDE.md`, `docs/methodology/skills-audit.md`) and the `apps/` workspace from the public repository via `.gitignore`; the plugin no longer ships the skills audit. Added secret and env ignore patterns.
