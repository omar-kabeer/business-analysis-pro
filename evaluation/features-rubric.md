# Features Evaluation Rubric

A repeatable rubric for judging whether a feature is well-formed and ready to decompose into stories. A feature is a distinct piece of functionality that delivers value and sits between an epic and its stories. Used by the product-owner and product-manager skills. Based on BABOK Agile Perspective (11.1).

## Scoring scale

For each dimension score 0 to 3: 0 absent, 1 weak, 2 adequate, 3 strong.

## Dimensions

| # | Dimension | What good looks like |
| --- | --- | --- |
| 1 | Value | The feature delivers a clear unit of value to a user or the business. |
| 2 | Scope clear | The scope of the feature and what it excludes are clear. |
| 3 | Decomposable | The feature can be broken into stories. |
| 4 | Acceptance | Acceptance criteria for the feature are stated. |
| 5 | Sized | The feature is sized well enough to plan a release around. |
| 6 | Prioritised | The feature has a priority relative to others. |
| 7 | Traceable | The feature traces to its epic and to a goal. |

## Result

Total the scores (maximum 21):

- Pass: 17 or higher with no dimension at 0.
- Pass with changes: 12 to 16, or a single quick-to-fix dimension at 1.
- Fail: below 12, or any dimension at 0.

Record findings by severity with a specific fix, and route material issues back to the product-owner skill.
