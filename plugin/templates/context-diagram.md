# Context Diagram

## Purpose

Show a system or solution in the middle, the external actors and systems it interacts with around it, and the data that crosses the boundary. It answers who and what the system talks to and what information flows, before any internal detail. Grounded in the architecture integration-patterns reference and BABOK Scope Modelling (10.41) and Interface Analysis (10.24).

## Boundary notes

State what is deliberately out of scope, and any assumptions about the boundary.

## Textual diagram

Represent the diagram in text if a drawing is not attached: the system in the centre, each external entity, and a labelled flow in each direction. Attach or link a drawn version where available.

## Review criteria

- The system boundary is explicit; in-scope and out-of-scope are clear.
- Every external entity has at least one labelled data flow.
- The diagram stays at the context level, with no internal detail.
