# Domain Pack Template

Copy this folder to `domain-packs/<domain-name>/` and fill it in. Keep the pack focused: enough to make an analyst competent in the domain, not an encyclopaedia.

## Recommended structure

- `overview.md`: what the domain is, when to load this pack, and how it plugs into the skills.
- `terminology.md`: the domain's key terms and concepts, defined plainly.
- `regulation.md`: the laws, standards, and standards bodies that shape work in the domain, with a note to verify current status because rules change.
- `deliverables/`: 3 to 5 domain-specific templates that the core template library does not cover.

## Standards to follow

- House style: no em dashes; run the natural-prose-editor pass on prose.
- Cite sources for facts that change over time (regulations, standards versions, deadlines), and date them.
- Keep deliverables domain-specific; general deliverables belong in the top-level `templates/`.
- Reference the relevant core skills and templates rather than duplicating them.
