# Current State Assessment

## Purpose

Understand the business need in the context of the enterprise as it is today, so the change has enough context to define a sensible future state and change strategy. This is the working form of the BABOK Analyze Current State task (6.1) and its output, the Current State Description. Describe only as much of the current state as the change requires; full detail everywhere is rarely needed.

## Inputs

Confirmed elicitation results, the stated needs, organisational strategy, and any existing process, capability, or architecture documentation.

## 1. Business need

State the problem or opportunity of strategic importance, expressed from the perspective of the enterprise rather than any single stakeholder. Question any presumed solution buried in the statement so the real problem is solved. Quantify the impact where possible.

## 2. Organisational structure and culture

Describe the formal reporting structure and the cultural factors (values, attitudes, ways of working) that could aid or limit the change.

## 4. Technology and infrastructure

Summarise the systems, data, and infrastructure that support the current state and any known limitations.

## 5. Policies

Note the business policies, rules, and standards that govern how work is done today and that a solution must respect or change.

## 6. Business architecture

Describe how the components above fit together: value streams, information flows, and the relationships among capabilities, processes, and systems.

## 7. Internal assets

Record the resources the enterprise can draw on (people, knowledge, financial, physical, and intangible assets such as brand or reputation).

## Output: current state description

Summarise the above into a concise statement of where the enterprise is today and why the need matters now. This becomes the baseline for the future state and gap analysis.

## Assumptions

List anything taken as true (for example, that documented processes match actual practice) and flag it for confirmation.

## Risks

Anchoring on the current state can entrench existing solutions. Keep the need, not the current design, at the centre so the future state stays open.

## Review criteria

- The business need is expressed from the enterprise perspective and the root cause is explored.
- Each relevant dimension (structure, capabilities, technology, policies, architecture, assets, external influencers) is covered to the depth the change requires.
- Claims are sourced or marked as assumptions.
- The current state description gives a clear baseline for future-state work.
